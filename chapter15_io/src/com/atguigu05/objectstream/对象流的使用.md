## 对象流的使用

### 数据流的使用（了解）

* `DataOutputStream`: 可以将内存中的基本数据类型，以及String类型的变量，写出到具体文件中。
* `DataInputStream`: 可以将文件中保存的数据还原为内存中的基本数据类型的变量，以及String类型的变量。

#### 数据流/对象流 DataInputStream/ObjectInputStream 的方法

* `byte readByte()`: 读取一个字节。
* `short readShort()`: 读取一个short。
* `int readInt()`: 读取一个int。
* `long readLong()`: 读取一个long。
* `float readFloat()`: 读取一个float。
* `double readDouble()`: 读取一个double。
* `char readChar()`: 读取一个char。
* `boolean readBoolean()`: 读取一个boolean。
* `String readUTF()`: 读取修改后的 UTF-8 格式字符串。
* `void readFully(byte[] b)`: 读取一个字节数组。

### 对象流的使用

#### API

* `ObjectInputStream`: 将文件中保存的对象的数据，以反序列化的形式读取出来使用。
* `ObjectOutputStream`: 将内存中的 Java 对象，以序列化的形式写出到文件中去。

#### 作用

可以读写基本数据类型的变量、引用数据类型的变量。

#### 对象的序列化机制

`对象序列化机制`允许把内存中的Java对象转换为平台无关的二进制流，从而允许把这种二进制流持久地保存在磁盘上，或通过网络将这种二进制流传输到另一个网络节点。//
当其他程序获取了这种二进制流，就可以恢复成原来的Java对象。

* 序列化过程：使用 `ObjectOutputStream` 流实现。将内存中的 java 对象保存在文件中或通过网络传输出去。
    * 用一个字节序列可以表示一个对象，该字节序列包含该`对象的类型`和`对象中存储的属性`等信息。字节序列写出到文件之后，相当于文件中
      `持久保存`了一个对象的信息。
* 反序列化过程：使用 `ObjectInputStream` 流实现。将文件中的数据或网络传输过来的数据还原为内存中的java对象。
    * 该字节序列还可以从文件中读取回来，重构对象，对他进行`反序列化`。`对象的数据`、`对象的类型`和`对象中存储的数据`
      信息，都可以用来在内存中创建对象。

#### 自定义类要想实现序列化机制，需要满足：

* 自定义类需要实现接口：`Serializable`。`Serializable` 是一个`标记接口`。不实现此接口的类将不会使任何状态序列化或反序列化，会抛出
  `NotSerializableException` 异常。
* 要求自定义类声明一个全局常量：`static final long serialVersionUID = 42L`;用来唯一的标识当前的类。
* 要求自定义类的各个属性也必须是可序列化的。
    * 对于基本数据类型的属性，默认就是可以序列化的
    * 对于引用数据类型的属性：要求实现 `Serializable` 接口

注意点：

* 如果不声明全局常量 `serialVersionUID`，系统会自动声明生成一个针对于当前类的 `serialVersionUID`。如果修改此类的话，会导致
  `serialVersionUID`
  变化，进而导致反序列化时，可能会出现 `InvalidClassException` 异常（修改了类，但未重新生成序列化文件时）。
* 类中的属性如果声明为 `transient` 或 `static`，则不会实现序列化。
    * 如果有一个属性不需要可序列化的，则该属性必须注明是瞬态的，使用 `transient` 关键字修饰。
    * 静态 `static` 变量的值不会序列化，因为静态变量的值不属于某个对象。
